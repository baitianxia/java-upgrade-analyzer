# 文档规则

## 权威与状态

- `docs/system/` 只描述当前系统语义。计划、测试通过次数和某次运行状态不能写成永久系统能力。
- `docs/project/current.md` 只导航当前工作上下文，不复制完整架构或质量合同。
- `docs/project/roadmap/` 是 planning-only；候选存在不表示已经授权、实施或验证。
- `docs/project/iterations/` 和 `docs/project/audits/` 保存有边界的项目记录；状态必须由实际证据给出，不能从标题或计划反推。
- `docs/archive/` 是历史材料，不进入默认开发阅读路径。

## 唯一所有者

同一当前规则只允许一个正文所有者。其他文档通过链接引用，不复制会独立漂移的规则。代码、Schema 或测试已能清楚定义的局部细节不在多份文档重复维护。

根目录 `SKILL.md`、`RUNBOOK.md` 和 `CHECKPOINT_RULES.md` 因 Skill 分发和运行时读取保留稳定路径。它们分别拥有执行、命令和最小交互合同；维护原则、项目计划和历史原因不得塞入这些运行时文档。

## 变更规则

- 系统语义变化：修改 `docs/system/` 中的唯一所有者；若根运行合同受影响，同步修改对应根文件。
- 新机会或未决问题：进入 Roadmap，明确事实、风险、进入条件和验收，不提前写成既成能力。
- 有时间边界的方案、实施和验证：进入新的项目开发记录；失败和未执行状态必须保留。
- 被替代正文：优先由 Git 历史保存；确需保留在工作树时移入 Archive 并在索引中说明替代关系。
- 历史项目记录中的旧路径默认保持原样，迁移映射由单独的 migration record 解释，避免改写当时语境。

## 链接与验证

- 导航使用相对 Markdown 链接；命令、程序读取路径和历史原文中的字面路径使用代码格式。
- 路径迁移必须同步更新当前系统文档、根运行文档、代码测试和活动夹具中的引用。
- 文档整理至少验证：工作树改动范围、所有当前 Markdown 相对链接、旧活动路径残留，以及直接受影响的文档契约测试。
